# 1.6.3 — Desktop: draw in a window

- Date: 2026-10-31
- TODO.md task: **1.6-draw**.
- Changes:
  - **Enter on `draw` in the desktop** runs the ASCII drawing program in a window, the same way as `calc` (`dk_run` in `kernel/desktop.asm`). Esc closes the window and the desktop is back.
  - **`draw` writes through `txt_base`.** The frame (`dr_frame`), the canvas and status rows (`dr_draw`) and the shared status-row routine `sb_row` (`kernel/editor.asm`) wrote to `0xB8000` directly. They now write to the screen `txt_base` names and set `txt_dirty`, so the window is redrawn before each key.
  - **Questions are visible in the window.** Before Save as, the unsaved-changes question on Esc and the brush question, `draw` moves the cursor to the message row when it runs in a window (`dr_askrow`). The window shows the rows that end at the cursor, so the question comes into view.
  - Banner `1.6.3`.
  - Regression checks:
    - `desktop-draw`: two plotted cells next to the canvas border (`|**`), read off the window.
    - `desktop-draw-save`: F2, a name, Esc twice; `cat` shows `**`.
    - `desktop-draw-back`: the desktop is there after Esc.
    - `desktop-draw-mem`: the page comes back after discarding a change.
    - `desktop-draw-text`: `systest: PASS` afterwards.
- Known limitations:
  - The window shows 52 of the 80 columns and 20 of the 25 rows: canvas columns 0 to 43 while drawing; the status row and the key help are off the window. The console widget draws no cursor, so the pen position is not marked.
  - `edit` and `vedit` still write to `0xB8000` directly (1.6-edit).
  - Tested in QEMU only.
- Status: implemented
