# 1.7.6 — Desktop entries as objects

- Date: 2026-10-31
- TODO.md task: **1.7-desktop**.
- Changes:
  - **The desktop's entries are objects** (`kernel/desktop.asm`, `apps/desktop.md`): a `DesktopObject` class (field `name`; methods `name`, and `open`, which opens nothing) and a `Program` class under it (field `entry`; `open` runs the entry in a window). The desktop makes one `Program` for each of files, calc, edit, vedit and draw when it starts, lists what each answers to `name`, and frees them when it closes.
  - **Enter sends `open`** to the chosen object instead of reading a table of entries.
  - **`files` opens in a window** too: the file browser already writes through `putc`, `puts` and `cls`.
  - Banner `1.7.6`.
  - Regression checks: `desktop-files`, `desktop-files-back`, `desktop-objs` (after the desktop closes, `objs` shows `Program < DesktopObject` and no live objects).
- Known limitations:
  - The window shows 20 of the browser's 25 rows: while the cursor is on its bottom row, the title and the first entries are above the window.
  - Opening a program from `files` inside the window runs it in the same window.
  - Tested in QEMU only.
- Status: implemented
- Design: `apps/desktop.md`
