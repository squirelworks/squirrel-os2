# 1.2.0 — Message queues between processes

- Date: 2026-10-31
- TODO.md task: **1.2-queue** (first half of milestone 1.2; **1.2-key-event** follows).
- Changes:
  - **`SYS_SEND` (27)** puts a four-byte message in another process's queue. It returns 0, −1 if no live process has that pid, or −2 if the receiver's queue is full. It never blocks.
  - **`SYS_RECV` (28)** takes the oldest message from the caller's own queue, and waits while the queue is empty.
  - Each process slot has a queue of 8 messages (new `kernel/msg.asm`). `spawn` empties it for the new process. `SYS_GETC` is unchanged.
  - **`msg`**, a new test program: fills its own queue and sees −2, drains it in order, sends to a missing pid and sees −1, then sends `ping` to a child that prints it.
  - Banner `1.2.0`. 29 system calls (0–28).
  - Regression checks: `msg` (`msg: queue full (-2)`, `msg: child got ping`, `msg: PASS`); `up-ls` counts 22 programs.
- Known limitations: no timeout on `SYS_RECV`, no way to tell the sender, four bytes per message.
- Status: implemented
- Design: `kernel/messages.md`
