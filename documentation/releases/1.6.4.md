# 1.6.4 — Desktop: edit and vedit in windows

- Date: 2026-10-31
- TODO.md task: **1.6-edit**.
- Numbering: built as 1.6.2, renumbered 1.6.4 because 1.6.3 (`draw` in a window) reached `main` first. There is no 1.6.2.
- Changes:
  - **Enter on `edit` or `vedit` in the desktop** opens the editor in a window, with an empty buffer. Ctrl+S or F2 asks for a file name and saves; Esc closes the window (after asking, if there are unsaved changes) and the desktop is back.
  - **The editor writes through `txt_base`** like `putc`, and sets `txt_dirty`, so its screen shows in the window.
  - **`txt_cols` and `txt_rows`** (80 and 25 by default) say how much of the text screen a program can see. The desktop sets them to 52 and 20 while a program runs in a window. The editor sizes its text area, status row and message row from them, so its status and message rows are visible in the window. The key reminder on `edit`'s status row is left out when it does not fit.
  - `sb_row`, which `draw` shares, pads to `txt_cols`, so `draw` in a window writes only the 52 columns shown.
  - **Console widget**: a cell with a background colour (the editor's status row) is drawn inverted, and the cursor's cell is inverted (a block cursor).
  - Banner `1.6.4`.
  - Regression checks:
    - `desktop-edit`: the typed text and the status row, read off the window.
    - `desktop-edit-save`, `desktop-vedit-save`: text saved from the window is what `cat` shows afterwards.
    - `desktop-edit-mem`: the page comes back after an unsaved buffer is discarded.
- Known limitations:
  - The editor opens with an empty buffer; there is no way yet to pick a file to open from the desktop.
  - Tested in QEMU only.
- Status: implemented
