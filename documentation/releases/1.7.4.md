# 1.7.4 — Installer: copy the system to the target

- Date: 2026-10-31
- TODO.md task: **I.3-copy**.
- Changes:
  - **`install copy`** asks y/n, then copies sectors 1 to 192 of the boot disk (the kernel image the boot sector loads) to the same sectors of the target, each one read back and compared, and every file in the root of the data disk into the root of the target's SQFS partition, through the loader's 64 KB staging buffer. One line per file, then the count. Subdirectories are not copied; a file over 64 KB is skipped (`kernel/install.asm`).
  - **The boot-disk test also compares the end of sector 0** (disk signature, partition table, `55 AA`) with the boot sector still in memory at `0x7C00`, so a target that holds a copy of the kernel is not taken for the boot disk.
  - Banner `1.7.4`.
  - Regression checks: `install-copy-esc`, `install-copy-esc-blank` (sector 1 still blank on the host), `install-copy`, `install-copied` (on the host: the kernel sectors match `os.img`, and every root file of the data disk matches its copy, through `tools/sqfs.py`), `install-after-copy`.
- Known limitations:
  - The kernel is read back from the boot disk, so the boot disk must be an IDE disk (not a USB stick, CD or floppy).
  - The target does not boot yet (I.4).
  - Tested in QEMU only.
- Status: implemented
