# 1.1.1 — Threads share a program's memory

- Date: 2026-10-31
- TODO.md task: **1.1-thread** (second half of milestone 1.1, which is now complete).
- Changes:
  - **The thread primitive, documented.** `SYS_SPAWN` with an entry in the program's own image starts a thread. `proc_spawn` already gave the child the parent's address space with a reference; `kernel/processes.md` now names this the thread primitive and says what a thread shares (code, data, heap) and what it owns (pid, stack, FPU registers, exit code). No kernel code changes; no priority field and no second scheduler.
  - **`thread`**, a new test program: it and a thread it spawns each add 1000 to one counter, yielding every 100 steps, then it checks the total (2000) and the thread's exit code (1000) and prints `thread: PASS`.
  - Banner `1.1.1`.
  - Regression checks: `thread`; `up-ls` counts 21 programs.
- Known limitations: no locks or other synchronization calls; threads coordinate through `yield`, `wait` and single-instruction updates.
- Status: implemented
- Design: `kernel/processes.md`
