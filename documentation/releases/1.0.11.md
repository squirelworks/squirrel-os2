# 1.0.11 — One-level undo in the editors

- Date: 2026-10-31
- TODO.md task: **1.0-edit-undo**.
- Changes:
  - **Ctrl+Z** in `edit` and `vedit` takes back the last edit: a typed key, Enter, Backspace, Delete, or Tab (all four spaces at once). It restores the text, the cursor and the modified flag. There is one level, so a second Ctrl+Z says `Nothing to undo.`
  - **The snapshot.** Before each edit, `ed_snap` copies the buffer to four pages from `pg_alloc`. The editor takes them when it starts (`ed_undo_init`) and frees them when it exits (`ed_undo_free`). `mem` after the editor shows the same free count as before.
    - The kernel scratch area had no free 16 KB left, which is why the copy uses pages from the allocator.
  - Banner `1.0.11`.
  - Regression checks:
    - `ed-undo`: type, undo, and the character is gone;
    - `ed-undo-once`: a second undo erases nothing more;
    - `ed-undo-bs`, `ed-undo-tab`;
    - `ed-undo-mem`: no pages leak.
- Fixed later (issue #47): an undo after Ctrl+S restored the modified flag as clean, so Esc quit without the `Unsaved changes` prompt and the undone text was lost. `ed_save` now sets the undo copy's flag to modified. Regression check `ed-undo-save`.
