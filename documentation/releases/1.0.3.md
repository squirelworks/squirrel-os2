# 1.0.3 — Programs read why a file call failed

- Date: 2026-10-31
- TODO.md task: **1.0-errno**.
- Changes:
  - **`SYS_FSERROR` (26).** `ebx` = buffer, `ecx` = its size. It returns the `FE_*` code of the last failed file call. The buffer gets the words the shell prints for that code, zero-terminated and without the newline.
    - `Not found` comes from the string table, so it follows `lang`, the same as in the shell.
    - The reason is the system-wide `fs_errno`, so a program asks right after the call that failed.
    - The kernel routine is `fs_error_text`, and the number is in `programs/sqx.inc`.
  - **New program `errno`.** `run errno <name>` opens the name and, when that fails, prints `errno: ` and the reason. For example:
    - `run errno missing` prints `errno: Not found`, as `cat missing` does.
    - On a directory it prints `errno: Is a directory`, as `cat` does.
  - Banner `1.0.3`.
  - Regression checks: `errno-nf`, `errno-dir` and `errno-la` (Latin: `Non inventum`). `up-ls` counts the new program.
- Status: implemented
