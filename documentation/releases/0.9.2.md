# 0.9.2 — Stability and polish pass

- Date: 2026-10-31
- Changes:
  - **File-system errors say why.** `fs_errno` records the reason for every failure. The shell prints it instead of a bare `error`, for example `Already exists`, `Bad name: 1 to 15 characters, not . or ..`, `No such directory`, `Directory not empty`, `That is the current directory`, `Is a directory`, `Disk full`, `Directory table full (64 entries)`. `cat` of a directory says `Is a directory` rather than `Not found`.
  - **Usage hints.** `put`, `mk`, `rm`, `mv`, `mkdir`, `cat`, `run` and `batch` typed alone print a `Usage:` line instead of `Unknown command`. `echo` alone prints an empty line. `mv` with one name prints its usage instead of trying to move the file onto itself.
  - **`mv` into a directory.** `mv notes docs` and `mv notes ..` move the entry into that directory under its own name.
  - **The browser shows directories.** Directories are listed as `name/ <dir>`, Enter goes into one, and `../` goes back up. The title shows the directory. A refused delete, such as a directory that is not empty, now says why instead of silently doing nothing.
  - **Paths in the apps.** `run edit`, `run vedit` and `run draw` take a path of up to 63 characters, as do their save-as prompts. Before, the name was cut to 15 characters, so `run edit docs/notes.txt` opened `docs/notes.txt` cut short.
  - Opening a directory in `edit`, `vedit` or `draw` used to claim `New file`, and the save then failed with `Disk error.`. It now shows the reason and starts untitled. Every failed save shows its reason, and a bad name makes the next save ask again.
  - Regression checks: `sh-usage`, `sh-unknown`, `fs-e-exists`, `fs-e-name`, `fs-e-nodir`, `fs-e-isdir`, `fs-e-notempty`, `fs-mv-into`, `fs-mv-up`, `ed-dir`, `ed-path-w`, `ed-path-r`, `fb-dir`, `fb-dir-up`.
- Bugs found on the way (fixed): KB-8, KB-9 and KB-10 in `knownbugs.md`.
- Status: implemented
- Design: `kernel/filesystem.md` (error reasons), `apps/files.md`, `apps/editors.md`, `kernel/shell.md`
