# 2.9.0 — Everyday long-mode kernel (`2.9-lm-kernel`)

**Date:** 2026-11-16  
**Mark:** M6 in `TO_3.0.0.md`  
**Lane:** `-b55f`

## Summary

The long-mode build flavour (`LM_BOOT64` / `os-lm64.img`) is an everyday regress
target under `qemu-system-x86_64`, beside the BIOS/`i386` flavour (`os.img` under
`qemu-system-i386`). Both flavours run in CI. This ticks `2.9-lm-kernel` and
jumps the banner to **2.9.0**.

## Changes

- `vm_map_range` under permanent stay no longer treats the PML4 as a PAE PDPT
  (that corrupted high MMIO maps). It maps the process PAE PDPT when needed and
  refreshes the LM wrappers so VBE / desktop work on `os-lm64.img`.
- Everyday 64-bit IRQ stubs save the GPRs `lm64_call32` clobbers (heap fill and
  similar ring-3 loops stay correct across ticks).
- `REGRESS_FLAVOUR=i386|lm64` in `tools/regress.sh`; lm64 boots `os-lm64.img`
  under `qemu-system-x86_64`. Foreign personality checks (Linux / Win32 / BSD /
  LX) and multi-CPU AP ring-3 (`smpspin-4` / `smp-*`) skip on lm64 until later
  work (`2.9-syscall64` / AP long-mode entry).
- CI regress shards run both flavours (2 × 4).

## Checks

- Full `tools/regress.sh` with `REGRESS_FLAVOUR=i386` (default)
- Full `tools/regress.sh` with `REGRESS_FLAVOUR=lm64`
- Existing `lm-boot64*`, `lm64-hello`, `lm64-ring3` unchanged

## Limits

- Linux/BSD/Win32 under stay still need a returnable personality body
  (`2.9-syscall64` / #221).
- APs park under stay but do not yet run ring-3 in long mode.
- ELF64 `syscall`/`sysret` is M7, not this mark.
