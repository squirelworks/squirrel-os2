# 1.7.2 — Installer: target disk, partition table and SQFS

- Date: 2026-10-31
- TODO.md tasks: **I.1-target** (merged without a version of its own) and **I.2-format**.
- Changes:
  - **The ATA driver sees four drives.** The secondary IDE channel (`0x170`, control `0x376`) is probed as drives 2 and 3. They have no device-table entry, so programs cannot reach them (`kernel/ata.asm`). `disk` lists all four.
  - **`install`** lists the drives and names the target: the first present drive that is neither the data disk (drive 1) nor the boot disk. The boot disk is found by content: its sector 1 starts with the running kernel's code (`kernel/install.asm`).
  - **`install part`** asks y/n, then writes an MBR with one type-`7F` partition from LBA 2048 to the end of the target, reads it back and shows it.
  - **`install format`** asks y/n, then formats SQFS with an empty root in that partition. **`install ls`** lists the root.
  - **The file system reaches its disk through `fs_dev`** (`kernel/fs.asm`). The installer points it at the partition only while `install format` or `install ls` runs, then loads the data disk again with the same current directory and open files. `fs_format_empty` formats without the built-in files.
  - `tools/qemu_screen.py --target IMG` attaches a scratch image as secondary master.
  - Banner `1.7.2`.
  - Regression checks (all on a fresh 16 MiB scratch image): `install-list`, `install-esc`, `install-esc-blank`, `install-fmt-nopart`, `install-part`, `install-mbr`, `install-again`, `install-ls-nofs`, `install-fmt-esc`, `install-fmt-esc-blank`, `install-format`, `install-sqfs`, `install-ls` (after a reboot), `install-back`, `install-none`. `install-mbr` and `install-sqfs` read the disk on the host.
- Known limitations:
  - BIOS boot and IDE/ATA disks only, LBA28. Newer PCs need the Modern hardware milestone first.
  - The target is not bootable yet (I.4) and holds no files yet (I.3).
  - Installer messages are English only until the I.5 `install` program.
  - Tested in QEMU only.
