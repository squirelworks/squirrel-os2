# 1.3.0 — Graphics mode and a pixel

- Date: 2026-10-31
- TODO.md task: **1.3-pixel** (first of milestone 1.3; **1.3-line-fill**, **1.3-text** and **1.3-graph** follow).
- Changes:
  - New `kernel/gfx.asm`: `gfx_mode13` switches to 320 × 200 × 256 (VGA mode 13h) by writing the VGA registers directly, and `gfx_text` puts the 80 × 25 text mode back. `gfx_putpixel` and `gfx_getpixel` write and read one pixel.
  - **`gfxtest`**, a new shell test command: graphics mode, two colours written to one pixel and each read back, text mode again, then `gfxtest: PASS` or `FAIL`. The banner's test list names it.
  - Banner `1.3.0`.
  - Regression checks: `gfxtest`; `gfx-text` (`systest` still passes after `gfxtest`). With the mode switch taken out, `gfxtest` prints FAIL, because the graphics window is not mapped in text mode.
- Known limitations: pixels over the text area or the font change them when text mode returns (`kernel/graphics.md`). No graphics system calls yet. Tested in QEMU only.
- Status: implemented
- Design: `kernel/graphics.md`
