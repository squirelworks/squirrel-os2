# 1.1.0 — The timer preempts spinning programs

- Date: 2026-10-31
- TODO.md task: **1.1-preempt** (first half of milestone 1.1; threads follow in **1.1-thread**).
- Changes:
  - **Time slices.** Each process gets `SLICE_TICKS` = 5 timer ticks (50 ms) when it is switched in. `timer_isr` counts the slice down.
  - **Preemption.** When the slice is used up and the tick lands in a loaded program's code (`0x30000`–`0x3FFFF`), `proc_preempt` switches to the next ready process through the ordinary `proc_switch`. The program resumes where it was interrupted when its turn comes back.
  - **The kernel is not preempted.** A tick that lands in kernel code (the shell, a built-in app, or a system call) leaves the switch for a later tick. The kernel is not reentrant, so this keeps every existing path as it was; `proctest` and `yield` give the same output as before.
  - **`spin`**, a new test program: it spawns a second process in its own image, then spins without a system call until that process has printed. It prints `preempt: PASS`, or `FAIL` if the spin ran out first.
  - Banner `1.1.0`.
  - Regression checks: `sched-preempt` (the second process's line and `preempt: PASS`); `proctest` and `interleave` unchanged; `up-ls` counts 20 programs.
- Known limitations: built-in apps and long system calls still run until they yield or block. No priorities (a 2.0 item).
- Status: implemented
