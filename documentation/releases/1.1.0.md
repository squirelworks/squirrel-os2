# 1.1.0 — Preemptive scheduler and thread primitives

- Date: 2026-10-31
- Changes:
  - **Priorities.** Each process has a priority from 0 (background) to 3, with 1 as the default, inherited from its parent. The scheduler runs the highest-priority ready process and takes turns among equals.
  - **Preemption.** The 100 Hz timer gives each process a 50 ms slice. When a loaded program uses up its slice, the next timer tick inside it, or its next return from a syscall, switches to a ready process of the same or higher priority.
  - The kernel and the built-in apps are not preempted, because their shared state (console, file system, ATA) has no locks yet. They switch only where they yield or block, as before.
  - **Sleeping.** `SYS_SLEEP` (25) sleeps for a number of ticks. A process with nothing to run while others sleep halts the CPU until a sleeper wakes, instead of declaring a deadlock.
  - **Priority and time calls.** `SYS_SETPRIO` (26) sets the priority of the caller or of a pid. `SYS_TICKS` (27) reads the tick counter.
  - **FPU state.** Each process keeps its own FPU registers across switches (`fnsave`/`frstor`).
  - **Shell.** `sched` shows the mode, ticks and preemption count. `sched coop` and `sched preempt` switch modes. `prio <pid> <0-3>` sets a priority, and `ps` has a PRIO column.
  - **New program `spin`.** It checks preemption, priorities and sleep.
  - `tools/qemu_screen.py` understands `<pause>` (wait a second), so checks can give the guest time.
  - Regression checks: `sched-preempt`, `sched-prio`, `sched-sleep`, `sched-coop` (the same busy test fails without preemption, as it should), `sched-after`, `ps-prio`, `prio-set`, `prio-bad`.
- Status: implemented
- Design: `documentation/kernel/processes.md` (scheduling policy, threads), `kernel/syscalls.md`
