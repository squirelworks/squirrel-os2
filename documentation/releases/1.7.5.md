# 1.7.5 — Installer: the target boots on its own

- Date: 2026-10-31
- TODO.md task: **I.4-bootable**.
- Changes:
  - **`install boot`** needs the kernel on the target (I.3) and asks y/n. It then copies bytes 0 to 439 of the boot disk's sector 0 (the boot code) over the target's, keeps the target's disk signature and partition table, marks partition 1 active, writes the sector and reads it back (`kernel/install.asm`).
  - **An installed disk is a whole system.** At boot, with no data disk attached, `ins_mount_system` makes partition 1 of the boot disk the file system (`dev_sys`) when it holds SQFS, and says `File system: partition 1 of the boot disk (an installed system).` With a data disk attached, the data disk is used as before.
  - The partition devices (`dev_inst`, `dev_sys`) keep their start sector in the descriptor, and the installer's file-system switch returns to whichever device was in use.
  - `boot.asm` refuses to assemble past byte 440, so its code never overlaps the disk signature and partition table.
  - Banner `1.7.5`.
  - Regression checks: `install-boot-nokernel`, `install-boot-esc`, `install-boot-esc-blank`, `install-boot`, `install-bootsec` (on the host: boot code equal to `os.img`'s, partition active, table intact), `install-alone` (QEMU boots the target as its only disk and `cat` reads a copied file from its partition), `install-alone-boot`.
- Known limitations:
  - BIOS boot and IDE disks only. Tested in QEMU only.
