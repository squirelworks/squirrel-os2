# 1.0.4 — Zombies no longer fill the process table

- Date: 2026-10-31
- TODO.md task: **1.0-zombie**.
- Changes:
  - **Orphans are freed.** A zombie whose parent has exited can never be waited for. `proc_reap_orphans` frees all of them, and `spawn` and `ps` run it first.
  - **The oldest zombie gives way.** When `spawn` finds the table full, `proc_reclaim_zombie` frees the zombie with the lowest pid, and `spawn` tries again. A later `wait` for that pid returns −1.
  - `proc_free` releases a zombie's address space and frees its slot. `wait` uses it too.
  - Pids are still never reused.
  - **New program `zombie`.** It starts 12 threads in its own image and never waits for them, which is more than the 7 free slots. It then spawns one more and waits for it, and prints `zombie: PASS`.
    - Before this change it stopped with `process table full of zombies`, and `ps` then listed six zombies.
  - Banner `1.0.4`.
  - Regression checks:
    - `zombie`;
    - `zombie-ps`: after the run, `ps | run wc` counts only the header and the shell;
    - `up-ls` counts the new program.
- Status: implemented
- Design: `kernel/processes.md` (Zombies nobody waits for)
