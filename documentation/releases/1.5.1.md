# 1.5.1 — Widgets: button

- Date: 2026-10-31
- TODO.md task: **1.5-button**.
- Changes:
  - **Button** (`kernel/widget.asm`). `wg_button` adds a boxed text with an event code; the process that adds it owns it. `wg_key` passes a key to the focused window's widgets. With Enter or Space, the window's button posts `MSG_BUTTON | code` to its owner through the 1.2 message queue (`msg_put`, as `SYS_SEND` does). Other keys come back unused (CF).
  - Widget records grow to 24 bytes (`WG_PID`, `WG_CODE`).
  - **`buttontest`**, a new interactive shell test command. It opens a window with a label and a button and passes keys to the widgets until Esc. Then it reads the shell's own queue and prints `button: PASS (n)` for n button events, `button: no event`, or `button: FAIL` if anything else arrived.
  - Banner `1.5.1`. The banner's Tests list takes a third line (`labeltest | buttontest`).
  - Regression checks: `buttontest`, `buttontest-2`, `buttontest-none`, `buttontest-text`. With the `msg_put` call taken out of `wg_key`, `buttontest` prints `button: no event`.
- Known limitations: one button per window takes the keys (the first); there is no way yet to move between widgets, and no pressed look. Kernel routines only. Tested in QEMU only.
- Status: implemented
