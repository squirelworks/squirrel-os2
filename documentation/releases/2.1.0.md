# 2.1.0 — Framebuffer graphics, ring 3, apps, games and foreign programs

- Date: 2026-11-13
- ROADMAP milestones finished: **2.1** framebuffer graphics and **2.4** ring 3 and protection. Also in this release: A.1, A.2 and C.9 apps, games G.1–G.5, G.7 and G.8, foreign programs P.1 and P.5, the first parts of C.2, P.2 and P.8, and the W.1 Warp theme constants and bevels. 2.2 and 2.3 (real windows on the framebuffer, the Program Manager desktop) are next.
- Pull requests: #134–#141, #143–#146 on top of 2.0.2.
- Changes:
  - **VBE framebuffer graphics (2.1, #134–#139, #143).** VBE linear-framebuffer modes 640×480, 800×600 and 1024×768 at 8, 16 and 32 bpp (Bochs/QEMU DISPI on the standard VGA, framebuffer from PCI BAR0), with mode 13h as the fallback. Double buffering with a VRAM back page, present by blit, and dirty rectangles so only changed regions are copied. A blitter (`gfx_copyrect`, overlap-safe) and clip rectangles (`gfx_setclip`/`gfx_noclip`) that every drawing primitive honours. `vbetest`, `cliptest` and `bevtest` check them by reading pixels back.
  - **Warp theme (W.1, #143).** Every window, widget and pointer colour is named once in `kernel/theme.inc`; `gfx_bevel` draws Warp-style raised and sunken bevels. The look is unchanged; the fonts part of W.1 is still open.
  - **Kernel above 1 MB (#140).** The kernel is now a 96 KB low image plus a high image loaded above 1 MB from sector 193 (hard disk, floppy and CD), which lifts the old 96 KB limit. The apps, editors, calculators, window manager, desktop, object system, loader and network stack moved there. The page allocator now starts at 2 MB. The installer copies both images.
  - **Ring 3 and protection (2.4, #141, #145).** Loaded programs and their threads run in ring 3 with supervisor-only kernel pages. Each program stack grows on demand inside a 512 KB window with a guard page ("stack overflow"). The syscall gate checks every pointer a program passes, including each ring-3 stack page it covers, and returns -1 for a bad one. A program that faults or runs a privileged instruction is ended on its own and the system keeps running.
  - **Graphical apps (A.1, A.2, C.2, C.9, #145).** A new `SYS_GUI` (35) call and a program toolkit (`programs/gui.inc`, `bmp.inc`) give ring-3 programs windows in the wm look, bevelled buttons, mouse and keyboard events and BMP files. New programs: `calculator` (standard and scientific), `clock`, `notepad`, `paint` (tools, undo/redo, BMP open/save), `viewer` (8/24-bit BMP, zoom, dither), `charmap`, `grapher` (up to four explicit, polar or parametric functions, zoom, pan, trace, roots, extrema, intersections), `topology` (Euler characteristic and Betti numbers) and `matrixgui` (up to 4×4: arithmetic, determinant, inverse, rank, solve).
  - **Games (G.1–G.5, G.7, G.8, #144).** `klondike`, `freecell`, `mines`, `hearts` (three AI players), `chess` (original move generator and alpha-beta search, SAN, PGN save; perft-checked), `mahjongg` (always-solvable deals) and `reversi`, on their own `games.img`. Each has a `run <game> test` self-check.
  - **Foreign programs (P.1, P.2, P.5, P.8, #146).** Static i386 Linux ELF programs run with an `int 0x80` personality covering file I/O, `brk`, anonymous `mmap`, TLS and about 40 more calls. Win32 console `.exe` files (including MinGW-built ones) run through `winrun`, a PE32 loader with a KERNEL32 shim and an msvcrt subset; `SYS_SETTLS` (36) gives them their TEB. DOS `.COM` and MZ `.EXE` programs run in `dosrun`, an 8086/186 interpreter with an `INT 21h` subset. All of them run in ring 3. Test programs are in `programs/` and on `dos.img`.
  - Banner `2.1.0`.
- Regression checks: `tools/regress.sh` has **495** checks, all passing (402 at 2.0.2). New ones include `vbetest` modes, `cliptest`, `bevtest`, `floppy-khigh`, `cd-khigh`, `khigh-missing`, `ring3`, `ring3-after`, `guitest` and the app self-checks, 14 game checks, and the `lx-*`, `win-*` and `dos-*` checks.
- Known limitations:
  - The desktop and window manager still draw in mode 13h; moving them onto the VBE framebuffer is 2.2.
  - Linux signals are stubs (signal masks only). `run prog.com` does not yet start `dosrun` by itself, and DOS programs have no window of their own.
  - The grapher has no implicit curves, inequalities or sliders yet (rest of C.2). Bridge (G.6) is not there yet.
- Build and run: unchanged (`tools/build.sh`, `tools/run.sh`, `guides/getting-started.md`). `data.img` carries every program in `programs/`, so the new apps, games and foreign-program tests are on it; `run <name>` starts them.
- Post-merge checks on real hardware: boot from a USB stick or hard disk and from a floppy and confirm the high image loads (calc runs); run a program that faults and confirm the system stays up; the GUI apps with a real PS/2 or USB mouse; clipped drawing and bevels on a real VBE card.
- Design: `kernel/kernel-image.md`, `kernel/ring3.md`, `kernel/windows.md`, `kernel/syscalls.md`, `apps/games.md`, `architecture/foreign-compatibility.md`, `architecture/dos-personality.md`.
