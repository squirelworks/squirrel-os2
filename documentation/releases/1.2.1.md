# 1.2.1 — Key events in the message queue

- Date: 2026-10-31
- TODO.md task: **1.2-key-event** (second half of milestone 1.2, which is now complete).
- Changes:
  - **`SYS_KEYEVENTS` (29).** With `ebx` = 1 the caller also receives every key press in its message queue, as `MSG_KEY | c` (`MSG_KEY` = `0x4B000000`). `c` is the character `SYS_GETC` would return. `ebx` = 0 stops it. One process at a time; the newest caller takes over.
  - **The keyboard IRQ posts the event.** `kbd_isr` still queues the raw scancode, so `SYS_GETC`, the shell and the apps are unchanged. `key_event` (`kernel/msg.asm`) then decodes the scancode with the same tables and its own Shift state and posts it.
  - `SYS_SEND` and `SYS_RECV` now change a queue with interrupts off, because the IRQ can post at any time.
  - **`keyev`**, a new test program: reads one key from its queue and the same key with `SYS_GETC` and checks they match.
  - Banner `1.2.1`. 30 system calls (0–29).
  - Regression checks: `keyev` (`q`), `keyev-shift` (`Q`); `getc-echo` (`keys`) and the shell checks unchanged; `up-ls` counts 23 programs. `sh-ls-pipe` now looks for `demo2.bat`, because with one more program `elfhello` scrolls off the top of the `ls` listing.
- Known limitations: one receiver of key events; no key-release or modifier events, only characters.
- Status: implemented
- Design: `kernel/messages.md`
